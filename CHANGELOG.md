# Changelog

## 0.3.0 (2026-11-16)

- **A first task, on an empty board.** Before any agent has worked in a repository, the middle offers three tasks that only read the project: "What does this project do?", "How do I run this project?" and "Find likely bugs". Clicking one starts an agent on it at once, as typing it would. They go for good once an agent has worked there.
- **Every prompt goes to an agent.** Anything you type or say that is not one of Workbench's own commands (stop, what needs me, status, merge, throw away, forget, Full permissions), or an answer to what is on screen, starts an agent at once, exactly as you wrote it: "thanks", "hi", "how are you", a question about the project and pasted code with its first and last lines all go. Say it to Codex or Claude by name ("codex, …", "codex who are you?", "ask codex to …", "ask claude which tests are flaky") and only the name comes off: "please", "thanks", "which" and "that" go too, and so does an emoji ("codex 👍"). The same words said again start another agent, even while the first still works, and words that only share a few with an agent's task no longer show that agent instead. "status" is the status even while an agent asks you something, "never mind, stop" stops the agent in the middle, and pasted code that begins with `stop()` is a prompt like any other. There is no launch question for one agent any more, with Full permissions on or off; a line under the board says once what started ("Started Claude on “the login page is broken”."), and a card in the middle stays where it is. The agent's chip comes at once, and its copy is made ready before it runs: its files are copied, and the setup command's question comes by itself the first time, once for every agent started meanwhile. Workbench no longer answers "I did not catch that". The input is a box that grows with its text: Enter sends, Shift+Enter adds a line. Text too long to send in one go (more than 64 KB) stays in the box, and the line under the board says so; on the git screen too, whose input now keeps a paste's lines, and keeps words a failed request did not send; "um" or "hmm" alone, said aloud, sends nothing. The input's focus ring now shows in the ivory look too.
- **Words read by rules, not lists of phrases.** With no question before work any more, a misread would start a paid agent, so what you say is read by rules over the words. A stop word and what it stops, first, stop that, whatever you say after it: "stop it, it is deleting the wrong files", "kill it" with the reason on the next line, "pause it - I need to check", "stop the agent because it is looping", "stop all agents, the build is broken" and "stop everything it is deleting files" all stop, and start nothing, while "kill the help pages popup on mobile" is still work. "cancel it" stops the agent in the middle. With a card in the middle, a stop stops and the card stays. Words that begin with the card's yes or no answer it, whatever follows, and the rest starts nothing: "yes, and then tell me", "no, because the tests are red", "do it, thanks", "merge it because the tests pass". A yes with a condition ("yes, but not into main") or a question after it keeps the card, as a bare "yes" to throwing work away does. The setup command's question takes no yes at all, alone or with more after it: only "run it", "run the setup command", "run it first", "do it" or "do that" run it. Starting more than one agent from one sentence ("start three agents on the login page", "have two agents fix the flaky test", "start Claude and Codex on the parser") asks first, since each one spends: "Start three Claude agents on “the login page”?", with **Start them** and **Cancel**. One agent still starts at once. "looks good" (or "lgtm", "thanks" and the like) said while the middle shows a finished agent never starts an agent: it presses the button that means it there, or, where none does (work that can be merged, a failed check), says which answers there are. Naming a program alone ("codex", "the agent", "ask claude") while a card is in the middle keeps the card and asks what it should work on, and while an agent waits for your OK, "try again" keeps saying that it waits, as "retry" does.
- **The file view.** A files chip beside the git chip, or ⌘P (Ctrl+P off a Mac) anywhere, grows the middle into a sheet that shows one file at a time: your folder's or an agent's copy, with line numbers, gentle colours, the lines an agent changed marked in gold, and every hidden character shown. Find a file by a few letters, jump to a line ("40"), or find words in the files (⌘⇧F). **Edit** and **Save** (⌘S) keep the file's line endings; if an agent changed the file meanwhile, nothing is written until you choose. A file shown is checked every 2 seconds and read again when it changes. A save into the copy of an agent that has finished records its work and runs its checks again. Binary files, files over 1 MB, links and env files show but are not edited; env files show their values masked. On the git screen, a path in an agent's changes opens that file in its copy, at its first changed line.
- **The done tray.** An agent you are finished with leaves the board for a tray at the bottom left: its work merged or thrown away, or you said **Looks good**, **Dismiss** or **Not now** to it ("2 done, 1 not merged"). The others keep their lanes, and a new agent takes the one it left. Pick it in the tray to see it again; continue it, or send it a message, and it comes back to the board. A merge that did not go through keeps its agent on the board until it goes through or you dismiss it. On a crowded board, an agent with no room on its side waits in the tray too ("1 more working"). Typing "looks good" or "not now" at a finished agent presses the button that means it there, and never lets work you could merge go by an approving word.
- **Agents' copies can run the project.** Before a new agent starts, its copy of your repository gets the files git ignores that a project needs: your `.env` files and `node_modules`, or exactly what a `.worktreeinclude` file lists, as copies that take almost no disk on a Mac. Its card says what it copies, then what its copy has and what could not be copied, and the values in those `.env` files are hidden in what agents print (not plain words, numbers and addresses, such as `production`, unless the variable's name says secret). A `setup` command in `workbench.json`, such as `npm ci`, runs in each new copy before its agent starts, once you say **Run it** (only its own words run it, never a "yes"); Workbench asks again whenever it changes, and once for several agents started together. The question comes into the middle by itself, and while agents wait on it the git screen's band lights "Before agents start".
- **Full permissions.** A button in the top band, beside Agents & keys, for when you want agents to stop asking. Turning it on asks first ("Let agents do anything without asking?"), and the questions already waiting are allowed too. While it is on, it is lit amber and every step that would wait for your OK runs, counted as an automatic approval, except a step that names Claude Code's own settings: a command or another service's tool that names them asks as it would without full permissions, saying only that the agent wants to run a command or use that tool, never what the step would do with them, and that full permissions do not cover it. Edits to those settings, and helpers that would work elsewhere, are refused, and so is an edit whose landing place Workbench cannot tell, or to a file also linked from another place on disk. Edits are checked, and commands only on a best-effort basis (a patch such as `git apply`, code an interpreter runs, and names built at run time can reach those settings without naming them). A command too long or too involved to check at once asks too, and every step is checked in a fixed time, however long its command. A find that only lists runs, even with a pattern that leaves hidden files out (`find . -not -path '*/.*'`, an Explore helper's usual first command); one that deletes or runs something on files that could be those settings asks. It stays on across restarts, and Workbench says so when it starts; pressing it again, or saying "ask first", turns it off at once. "full permissions", "stop asking" and "allow everything" ask for it in words. In the demo it lasts for that run only.

## 0.2.0 (2026-11-14)

- **Agents & keys.** A panel on the page that helps install Claude Code and Codex, signs them in through the browser or gives them an API key, and picks the agent for new work. An agent connected while Workbench runs takes work at once, and earlier agents that used it can be continued again.
- **The key store.** Keys you give agents are kept in the login keychain on a Mac (on Linux, a keyring or private files). They reach only the agents you choose and their checks, show only as their last four characters, are hidden in everything agents print, and are never sent from the board's input.
- **GitHub and cloning.** Sign in to GitHub with no token, through GitHub's own `gh`, which Workbench downloads and checks itself. Clone a repository with `--clone` or from the Mac app, private ones included. Where `gh` cannot run, a token works instead.
- **Git in an agent's folder.** Agents may run git's own commands in their own folder, Codex agents too. Git that reaches past an agent's work, such as a force push, waits for your OK and says what it would change. Agents & keys saves git's name and email, which merging needs.
- **Free text starts work.** Anything you type that says what you want, such as "the login page is broken" or "why is the build slow?", becomes a new agent's task once you say yes. Say an agent's name to pick it.
- **The Mac app** clones repositories, lists your GitHub repositories, signs you in to GitHub, and offers to install git. With no agent ready, it opens the board anyway, and Agents & keys helps.
- **More spending limit, in place.** A Claude Code agent stopped by its spending limit can be given one more limit for this run (**Give it $2.00 more**), and it continues where it left off. Before, it could go on only after Workbench was started again.
- **A release you can sign.** The Mac app's build can sign it with a Developer ID, with the hardened runtime, and have Apple notarize it. The app carries the licenses of Node, npm and its typeface, and every disk image comes with a SHA-256 checksum.
- **Words that match what happens.** A Codex agent's launch card no longer promises a spending limit Codex does not have, and Agents & keys says which name and email merges use when a repository has its own.
- **Security review before release.** A fresh review reproduced each issue against the real code, and each is fixed and pinned by tests:
  - Permissions: zsh's `=program` words and wildcards that reach through links no longer slip past the checks. Git that reaches other working copies, other repositories' addresses, patches (`git apply`, `git am`), `git replace`, upkeep that deletes for good and settings outside the folder now waits for your OK. Claude Code's protected files are known by name the way the Mac's disks compare names.
  - The page: each run serves it on a free port picked at random, so nothing another program left at an earlier address applies; the Mac app's web view keeps nothing between runs. Your look and detail are kept in `~/.workbench/prefs.json` instead. The page's key is never on a command line.
  - Files: Workbench keeps its temporary files in a private folder under `~/.workbench`, runs its own merges with no git hooks, installs the very `gh` it checked, and makes agents' folders private to your account.
- **Tests on every push.** GitHub runs `npm test` on Linux with Node 22, 24 and 26.
- **Fixes.** Codex agents start when Workbench runs with `--model`, which now names only the Claude model. A slow check for passwords in pasted links made `npm test` fail on a busy Mac; it now takes milliseconds. An agent that fails after it started is now in the log, with the reason.

## 0.1.0

The first preview, for the Mac.

- The board: each agent is a chip on its own lane, and the middle shows what needs you, in plain language. You answer by typing, or by holding the space bar to talk.
- Claude Code and Codex agents, each in its own git worktree and branch. Claude Code agents wait for your OK before anything beyond safe work in their own folder, and have a spending limit.
- Source control: the git screen draws your branch and your agents' branches. Review an agent's changes, then merge them into your branch or throw them away; a hidden copy stays in git.
- Earlier agents come back when Workbench starts again, and can be continued or forgotten.
- Checks and rules in `workbench.json`, run on an agent's work when it is done.
- The Mac app: Workbench in its own window, with Node inside.
- A demo with simulated agents and machines, where nothing is spent.
